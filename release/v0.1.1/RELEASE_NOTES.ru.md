# SHMAX v0.1.1 — исправление фотоальбомов MAX

Подготовленный stable patch; публикация ожидает разрешения владельца.

Исправлена передача нескольких поддерживаемых вложений из одного сообщения MAX.
Ранее bridge скачивал фотографии, но оставлял только первую; остальные превращал
в уведомление о неподдерживаемом вложении до отправки в Telegram.

Bot API теперь отправляет последовательные фотографии группами по 2–10,
сохраняет порядок, forum topic, авторство и reply. Одно фото использует прежний
путь. Документы и другие поддерживаемые типы передаются отдельно. Для адаптера
без групп и явного отказа Bot API предусмотрена последовательная отправка;
неоднозначный timeout не вызывает слепую замену группы отдельными сообщениями.

Очередь сохраняет прогресс после подтверждённых отправок. Retry/restart не
повторяет уже подтверждённые и записанные в checkpoint фото. Все message IDs
альбома связаны с каноническим MAX message ID, включая replies к последнему фото.
Новая additive migration создаёт таблицу aliases, не меняя существующие данные.

Временная недоступность файла повторяется в пределах существующей политики
(8 попыток). После исчерпания попыток остальные валидные вложения доставляются,
а очередь отмечает частичный сбой; это не выдаётся за полную успешную доставку.
Истёкший photo URL может обновиться через реальный PyMax get_messages по source
chat/message/photo ID. chat_id=0 остаётся допустимым.

Ограничение: Telegram не предоставляет idempotency key. Если сервер принял запрос,
но ответ потерян или процесс погиб до durable checkpoint, повтор может дублировать
удалённую отправку. Ни фиктивного exactly-once, ни выдуманной per-photo частичной
ответной семантики sendMediaGroup не заявляется.

Нет обезличенного live payload проблемного шестикратного сообщения. Проверки
используют настоящие PhotoAttachment/Message установленного PyMax 2.4.1; неизвестные
gallery representations и live MAX/Telegram пока не подтверждены. Безопасная
локальная сводка metadata: scripts/summarize-max-attachments.py читает stdin и
выводит только типы, количество, наличие известных полей и размеры — без токенов,
URL, IDs, имён и текста. Raw input хранить только приватно.

Действие существующего пользователя — только обновление:

```bash
sudo shmax update /path/to/shmax-v0.1.1.tar.gz
```

Переустановка, повторный onboarding, смена bot token, MAX re-auth и повторный
выбор Xray не нужны. Existing signed one-line installer по-прежнему устанавливает
фактически опубликованный stable release; до публикации v0.1.1 это v0.1.0.
