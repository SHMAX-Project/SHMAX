# SHMAX v0.1.1 — фотоальбомы MAX → Telegram

Исправлена передача нескольких фотографий из одного сообщения MAX: раньше в Telegram попадало только первое фото, а остальные помечались как неподдерживаемые вложения.

- Нативные Telegram-альбомы по 2–10 последовательных фотографий с сохранением порядка, подписей, авторства, forum topic и replies. Одиночные фото отправляются прежним способом; другие поддерживаемые вложения — отдельно.
- Сохранение подтверждённого прогресса очереди при retry и перезапуске. Все ID сообщений альбома связаны с исходным сообщением MAX, включая ответы на последнее фото.
- Ограниченные повторы загрузки и обновление истёкших photo URLs через PyMax. После исчерпания попыток оставшиеся валидные вложения доставляются, а частичный сбой остаётся виден в очереди.
- Совместимость обновления 0.1.0 → 0.1.1: additive migration сохраняет данные; повторная настройка и переустановка не нужны.

Проверки: backend — 985 passed / 4 skipped; frontend — 46 passed; typecheck — PASS; 24 регрессионных сценария альбомов с моделями PyMax 2.4.1. Обновление и rollback проверены в изолированной Debian 13 amd64 VM с сохранением настроек, маршрутов, очереди, истории, зашифрованных секретов и синтетических файлов сессий. Финальные архивы проверены на соответствие публичному commit, целостность и корректную обработку подписанным установщиком.

Обновление существующей установки:

```bash
sudo shmax update
```

Ручное обновление скачанным production-архивом:

```bash
sudo shmax update /path/to/shmax-v0.1.1.tar.gz
```

Telegram не предоставляет idempotency key: потеря ответа после принятия запроса или сбой до сохранения checkpoint могут привести к повторной отправке. Неоднозначный timeout не запускает слепую замену альбома отдельными сообщениями.
