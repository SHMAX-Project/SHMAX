# SHMAX v0.1.0 — первый публичный выпуск (подготовлен, не опубликован)

SHMAX — независимый self-hosted шлюз MAX ↔ Telegram. Один обычный аккаунт MAX
связан с вашим Telegram Bot и приватной супергруппой-форумом: один выбранный чат
MAX соответствует одной теме Telegram. Не является продуктом MAX или Telegram.

- Автовосстановление сохранённого Telegram-транспорта с одним polling consumer.
- Проверенное локальное обновление из production-архива: резервная копия, health-проверка и откат.
- Нормализация прав приложения и метаданных Docker для запуска без root после извлечения с umask 077.
- Доставка в обе стороны, ответы с сопоставлением сообщений и управляемый доступ.
- Одобрение пользователей, роли и подписи операторов в MAX; Telegram admin
  автоматически не становится администратором SHMAX.
- Необязательная синхронизация участников существующим ботом через API ID/Hash;
  обнаружение пользователей через chat_member и сообщения остаётся доступным.
- Текст, фото, документы, поддерживаемое видео; статические стикеры как изображения,
  для анимированных/видео — preview или понятный fallback. Saved Messages `chat_id=0`
  является допустимым назначением. Совместимость PyMax 2.4.1 photoIds и document/file.
- Мастер настройки, пропуск после создания владельца, отдельные редакторы
  MAX/Telegram, контроль несохранённых данных, мобильный интерфейс и диагностика.
- Локальные копии и переносимый зашифрованный v2 export `.shmax`, восстановление
  на свежем владельце, сохранение конфигурации/БД/SecretStore и rollback.

**Платформа:** Debian 13 amd64, Docker + Compose v2, systemd. Владелец подтвердил
живую установку, мост/медиа, обновление с сохранением конфигурации, reboot и health.
ARMv7/ODROID-XU4 — экспериментальная проектная цель; физическая приёмка не завершена.
Другие платформы не объявляются прошедшими живую приёмку.

**Установка из проверенного production архива:** проверить SHA256SUMS, извлечь
`shmax-v0.1.0.tar.gz`, перейти в `shmax-v0.1.0`, изучить скрипт и выполнить
`sudo bash deploy/installer/install.sh --mode install`. См.
[установку](../../docs/ru/installation.md) и [первую настройку](../../docs/ru/first-setup.md).
Нужны собственные MAX-аккаунт, BotFather bot, приватная форум-группа и выбранный
сетевой транспорт. API ID/API Hash нужны только для необязательной member sync.

**Перенос:** защищать архив и пароль; локальная копия не эквивалентна encrypted
export. Остановить старый мост перед запуском восстановленного. Новые owner credentials
сохраняются, старые web sessions/admins отзываются; внешние сервисы могут потребовать
повторной авторизации. Физический перенос между архитектурами не подтверждён.

**Ограничения:** один paired forum; внешние протоколы и PyMax могут измениться.
Нативная анимация стикеров не обещается. При permanent/uncertain ошибках нужна
проверка оператора; отсутствие повторной доставки не гарантируется при сбое между
внешней отправкой и записью результата. Не раскрывать web UI без защиты.
