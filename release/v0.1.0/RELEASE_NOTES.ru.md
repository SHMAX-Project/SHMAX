# SHMAX v0.1.0

Первый выпуск SHMAX — шлюза между MAX и Telegram для собственного сервера.
SHMAX связывает выбранные чаты MAX с темами приватной Telegram-группы и
предоставляет веб-интерфейс для настройки подключений, маршрутов и прав доступа.

## Возможности выпуска

- Обмен текстом, фото, документами и поддерживаемым видео в обе стороны.
- Сопоставление ответов, подписи отправителей и маршрутизация по темам.
- Одобрение участников, роли, блокировки и необязательная синхронизация пользователей.
- Прямое подключение к Telegram, SOCKS5, HTTP-прокси и управляемый Xray.
- Автоматическое восстановление сохранённого Telegram-транспорта.
- Мастер первоначальной настройки, отдельные настройки интеграций и мобильный интерфейс.
- Локальные резервные копии и зашифрованный экспорт `.shmax` для переноса данных.
- Обновление из проверенного production-архива с резервной копией,
  контролем работоспособности и автоматическим откатом.
- Запуск контейнера без root и корректные права файлов приложения.

## Установка и обновление

Однострочный bootstrap: `install.sh` в официальном репозитории. Проверка подписи
RSA-3072/SHA-256 и контрольных сумм выполняется до запуска кода релиза.
Ручная установка из полного production-архива также поддерживается.
`sudo shmax update` получает последний подписанный стабильный выпуск;
`sudo shmax update /path/to/release.tar.gz` сохраняет сценарий локального обновления.
При отказе кандидата откат восстанавливает прежний образ и проверенную холодную копию данных.

## Требования и установка

Debian 13 amd64, Docker Engine, Compose v2 и systemd. Для установки нужны права
администратора сервера, собственный аккаунт MAX, Telegram-бот и приватная группа
с включёнными темами.

Скачайте `shmax-v0.1.0.tar.gz` и `SHA256SUMS`, проверьте контрольную сумму,
распакуйте архив и из каталога `shmax-v0.1.0` выполните:

```bash
sudo bash deploy/installer/install.sh --mode install
```

## Данные и безопасность

Конфигурация, база данных и авторизация сохраняются при обновлении.
Для переноса используйте зашифрованный экспорт и остановите исходный шлюз
перед запуском восстановленного экземпляра. Обычные локальные копии содержат
материал авторизации и требуют защищённого хранения.

[Резервные копии](../../docs/ru/backups.md) · [Восстановление](../../docs/ru/restore.md) ·
