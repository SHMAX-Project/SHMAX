# SHMAX v0.1.3 — исправление альбомов без подписи

## Исправления

- Альбом MAX без текста и подписи больше не падает до очереди, если display name отправителя отсутствует. Пустая подпись корректно обрабатывается как пустая строка. Порядок фотографий, маршрут и тема Telegram сохраняются.
- Проверка лимита подписи учитывает UTF-16; длинный текст сохраняется для отдельной отправки. Долговечная очередь, контрольные точки и native ID aliases сохранены.
- Исключение при обработке входящего сообщения создаёт ERROR `message.processing_failed` в журнале: направление, correlation ID и безопасный класс ошибки, без тела сообщения и текста исключения.

Дефект альбомов присутствовал в v0.1.1 и v0.1.2. Этот выпуск сохраняет остальные улучшения v0.1.2. Новых миграций базы и изменений формата сессий нет.

## Ограничения

Ошибка в журнале не является отдельным Telegram-уведомлением. Старые сообщения, не попавшие в очередь из-за исключения, автоматически не восстанавливаются. Ручной replay старых доставок не выполняется. Сетевой сбой после принятия отправки Telegram по-прежнему может привести к повтору.

## Проверки

Регрессии проверяют три фотографии без имени отправителя: без подписи, с подписью и на границе 1024 UTF-16 единиц, через реальную SQLite-очередь и тестовый транспорт; отдельно проверена видимость ошибки без приватного содержимого. Полные результаты входят в `validation.json` комплекта релиза. Production-проверка не отправляет тестовые сообщения в рабочие чаты.

## Обновление

```bash
sudo shmax update /path/to/shmax-v0.1.3.tar.gz
```

Используйте подписанный production-архив. Штатный updater создаёт локальную root-only холодную копию перед заменой контейнера и проверяет готовность; при отказе выполняется откат. Резервные копии и ключи не входят в релиз.
