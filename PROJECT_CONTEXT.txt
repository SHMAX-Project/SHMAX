# PROJECT_CONTEXT.txt — SHMAX

SHMAX — самостоятельный (self-hosted) шлюз MAX ↔ Telegram:
обычный аккаунт MAX подключается к приватной Telegram-супергруппе
с форум-темами (один чат MAX = одна тема, ответы в обе стороны,
медиа, ACL). Живая приёмка владельца: Debian 13 amd64. ODROID-XU4 (ARMv7) — экспериментальная цель, физическая приёмка не завершена;
приложение одноразово, данные постоянны в /var/lib/shmax.

## Безопасность

Токен бота, API Hash, Xray-подписка и VLESS/Trojan — в SecretStore
(/var/lib/shmax/secrets, AES-256-GCM). Сессия MAX — отдельный файл 0600.
Локальные копии могут содержать мастер-ключ и plaintext; portable v2 .shmax всегда зашифрован паролем целиком.
Portable v2 UI экспортирует один обязательно зашифрованный .shmax и предлагает
restore после создания нового владельца. Пароль храните отдельно; старые веб-сеансы
отзываются, Telegram ACL/подписи сохраняются. Не запускайте источник и назначение
одновременно. Никогда не передавайте секреты, сеансы, архивы или пароль в поддержку.

## Участники Telegram

MAX всегда direct. Полная синхронизация необязательна: API ID + API Hash из
my.telegram.org, существующий BOT, без userbot/человеческого входа. Импортирует
молчавших участников; ручная кнопка «Синхронизировать с Telegram» в Users.
Будущие изменения: chat_member; запасной способ: видимые сообщения. Новые
участники не одобрены/read_only; Telegram admin не даёт SHMAX admin. Отсутствие
настроек и ошибки sync не останавливают мост. getMe не доказывает доставку
сообщений конкретной группы; предупреждение Privacy Mode требует проверки
прав, BotFather и живого сообщения.
