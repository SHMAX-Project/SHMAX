# Telegram группа / форум / темы

1. Создайте группу, добавьте своего бота.
2. Включите «Темы» (Forum/Supergroup).
3. Сделайте бота администратором с правами отправки сообщений и управления темами.
4. В SHMAX нажмите «Получить одноразовый код».
5. Отправьте в **General**: `/shmax_connect <КОД>`.
6. SHMAX определит и проверит группу автоматически; вводить chat_id не нужно.

Если группа не подключается, проверьте темы, права бота, сеть Telegram,
живой слушатель и срок действия кода. В BotFather установите `/setprivacy` →
**Disable Privacy Mode**. Отсутствие команды само по себе не доказывает,
что Privacy Mode включён. Подробнее: [Telegram бот](telegram-bot.md).

`🔧 SHMAX` — системная тема для служебных уведомлений; в мост она не попадает.

## Автоматическое обнаружение участников

Полная синхронизация **необязательна** и может импортировать существующих
молчавших участников: им не нужно писать боту для появления в «Пользователях».

1. Получите Telegram **API ID и API Hash** на [my.telegram.org](https://my.telegram.org).
2. Откройте страницу **Telegram**, раздел «Синхронизация участников · необязательно».
3. Введите оба значения и нажмите «Сохранить настройки синхронизации».
   API Hash — секрет: не отправляйте его в поддержку, логи или чат.
4. На странице **Пользователи** (также на шаге Users мастера) нажмите
   **«Синхронизировать с Telegram»**. Проверьте результат, время попытки и
   числа найденных, новых и обновлённых участников. Неполный импорт не считается успехом.

Используется **существующий бот**, а не человеческий Telegram-аккаунт или
userbot. Для работы SHMAX не нужен вход по телефону, OTP или QR в Telegram.
Бот должен иметь доступ к подключённому форуму и необходимые права администратора;
ограничения Telegram могут помешать полной выгрузке списка. Другие боты исключаются.

После подключения группы и при восстановлении настроенной системы синхронизация
запускается в фоне; постоянного частого опроса списка нет. Будущие изменения
членства отслеживаются через `chat_member`. Видимые сообщения остаются запасным
способом обнаружения. Без API ID/API Hash полная выгрузка не выполняется — это
нормальное состояние, мост продолжает работать. Ошибка синхронизации также не
останавливает мост.

**Обнаружение не равно авторизации.** Новые пользователи не одобрены, не
заблокированы и имеют роль `read_only`. Статус администратора Telegram не даёт
роль администратора SHMAX. Существующие одобрение, блокировка, роль и локальный
ник сохраняются; доступом управляет администратор SHMAX на странице
[Пользователи](users-acl.md).

API Hash хранится зашифрованно в SecretStore и не возвращается после сохранения.
Сессия синхронизации существует только в памяти; дополнительных файлов сессии
для копирования нет. Пользователи и настройки входят в обычную резервную копию:
[состав и защита архива](backups.md). Сетевые ограничения описаны в
[Telegram сеть](telegram-network.md), технические пределы — в [архитектуре](architecture.md).

### Локальная подпись и синхронизация

«Подпись в MAX» (`nickname`) задаётся в карточке пользователя SHMAX. Синхронизация обновляет Telegram-имя, username, членство и статус Telegram-admin, сохраняя эту подпись и ACL. Например, после переименования Telegram-профиля подпись «Анна» продолжает давать `[Анна]: Клиенту уже ответили.` Профиль Telegram не изменяется. Подробнее: [Пользователи и ACL](users-acl.md#подпись-в-max).
