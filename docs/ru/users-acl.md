# Пользователи и ACL

- Telegram-пользователи НЕ получают право писать в MAX
  автоматически. Политика fail-closed.
- В v0.2.0 сначала выберите группу на странице «Пользователи»: одобрение, роль и запрет отправки задаются отдельно для неё. Ник остаётся общей локальной подписью пользователя.
- Роль определяет набор разрешений (например, `send_message`).
  Заблокированные и read-only писать в MAX не могут.
- MAX → Telegram требует действующей привязки и включённой проверенной группы; личность автора MAX используется для подписи, а не как Telegram-принципал разрешений.
- Ник (`/setname`) — как автор подписывается в MAX.


## Синхронизация участников

Чтобы импортировать существующих молчавших участников, на странице Telegram
сохраните необязательные API ID и API Hash из my.telegram.org. API Hash — секрет.
Используется существующий бот, без человеческого userbot. На странице
«Пользователи» нажмите «Синхронизировать с Telegram» и проверьте результат.
Им не нужно писать боту при настроенной полной синхронизации. Будущие изменения
членства приходят через chat_member; видимые сообщения остаются запасным способом.
Без настроек и при ошибке синхронизации мост продолжает работать.

Новые участники не одобрены и имеют роль read_only; Telegram admin не даёт
SHMAX admin. Существующие ACL и ник сохраняются. Подробнее:
[Telegram-группа](telegram-group.md#автоматическое-обнаружение-участников).

## Подпись в MAX

В карточке Telegram-пользователя администратор может задать «Подпись в MAX», проверить предпросмотр и сохранить её. Это существующее поле `nickname`: локальное имя автора в SHMAX, а не Telegram-профиль или роль. Например, подпись «Анна» даёт сообщение `[Анна]: Клиенту уже ответили.`

«Очистить» возвращает обычное имя Telegram; если его нет, используется @username, затем безопасное запасное имя. Подпись применяется ровно один раз к Telegram → MAX, включая ответы, медиа, подписи и текстовые запасные сообщения. Имена авторов MAX → Telegram остаются прежними.

Пробелы по краям удаляются; пустое значение снимает переопределение. Разрешены кириллица, латиница, emoji и обычная пунктуация, до 64 Unicode-символов. Переносы строк и управляющие символы запрещены. Изменение требует административной сессии и CSRF и не меняет одобрение, блокировку, роль или членство. Синхронизация участников, переименование Telegram-профиля и смена Telegram-admin никогда не перезаписывают локальную подпись.

## v0.2.0

Настройки маршрутов, подписей источника/автора и прав отправки задаются отдельно по Telegram-группам. Один чат MAX может иметь несколько назначений; админский обзор создаёт темы автоматически. Постоянные задания и соответствия сообщений разделены по назначениям; альбомы сохраняют состав и тему в каждой группе. Сеть MAX настраивается независимо от Telegram. См. [группы и права](multi-group.md), [сеть MAX](max-network.md), [медиа](media.md).
