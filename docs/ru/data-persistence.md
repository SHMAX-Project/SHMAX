# Карта файлов и персистентность

## ПРИЛОЖЕНИЕ ОДНОРАЗОВО. ДАННЫЕ ПОСТОЯННЫ.

```
/opt/shmax                      # деплой (заменяется обновлением)
├── compose.yaml                # операторская конфигурация (bind, порт) — сохраняется апдейтером
├── boot/shmax-boot.sh          # boot-оркестрация
├── install.sh
└── .env                        # операторское окружение — сохраняется

/var/lib/shmax                  # ПОСТОЯННЫЕ данные (никогда не удалять без purge)
├── db/shmax.db                 # SQLite (Alembic-миграции)
├── secrets/                    # SecretStore AES-256-GCM, мастер-ключ (0600)
├── sessions/max/               # сессия PyMax
├── sessions/telegram/          # каталог для совместимости; Bot API не пишет сессию
                               # member-sync: сессия только в памяти
├── state/                      # состояние (watchdogs, telegram_auto, setup_secret)
├── backups/                    # *.shmax (0600), pre-update/pre-restore копии
└── cache/                      # одноразовый кэш — можно удалять

/run/shmax/hostd.sock           # unix-сокет hostd (0660, группа shmax)
```

## Что можно удалять/пересоздавать

- `cache/` — да, в любой момент.
- Контейнер — можно пересоздать при сохранении монтирования `/var/lib/shmax`.
- Файлы приложения можно заменить; не удаляйте `/opt/shmax` целиком без сохранения
  операторских `compose.yaml` и `.env`. Апдейтер сохраняет их при замене.

## Что нельзя удалять без осознанного решения

- `/var/lib/shmax` целиком — это вся конфигурация, сессии и БД.
- `secrets/` — без него не расшифровать SecretStore.
- `sessions/` — придётся заново логиниться в MAX.

## Что переживает пересоздание контейнера

Всё в `/var/lib/shmax`: конфигурация, сессии, копии, история.

## Что попадает в резервную копию

БД (снапшот), SecretStore (зашифрованным) **и его мастер-ключ**, state, sessions,
xray-кэш выбора ноды. НЕ попадают: кэш, логи, tmp, сами копии
(исключено), симлинки наружу (отвергаются, live A7).

Обычный архив не зашифрован целиком: см. [защита копии](backups.md).
