# Модель безопасности

## Принципы

- Web-контейнер **не получает Docker socket**. Хост-операции —
  только через shmax-hostd: фиксированный набор операций,
  валидация аргументов, никаких shell-строк.
- Fail-closed: ACL, маршруты тем, фолбэки сети.
- Токены, API Hash и пароли прокси — в SecretStore (AES-256-GCM, ключ 0600).
  Сессия MAX — отдельный файл 0600; БД содержит идентификаторы пользователей и
  данные доставки. Не публикуйте БД, сессии, ключи или неочищенные логи.

## Механизмы

| Механизм | Реализация |
|---|---|
| Пароль админа | Argon2id |
| Сессии | подписанные cookie + таблица admin_sessions (отзыв) |
| CSRF | токен на мутациях (X-CSRF-Token) |
| Rate limiting | на чувствительных эндпоинтах |
| Заголовки | CSP/безопасные заголовки |
| Бэкапы | 0600/0700, симлинки наружу отвергаются |
| Обновления | SHA256 из доверенных манифестов, allowlist origin'ов, анти-SSRF |
| Xray | SOCKS только 127.0.0.1, конфиг 0600, без shell=True |

## Таблица секретов

| Секрет | Где хранится | Шифрование | Никогда |
|---|---|---|---|
| Токен бота | SecretStore | AES-256-GCM | в логи/поддержку/URL |
| MAX-сессия | sessions/max (SQLite) | файл 0600 | наружу |
| Xray подписка URL | SecretStore | AES-256-GCM | в логи |
| VLESS UUID / Trojan пароль | SecretStore + ephemeral конфиг 0600 | AES-256-GCM | в БД открытым текстом |
| GitHub token (опц.) | SecretStore | AES-256-GCM | на любые origin'ы кроме api.github.com |
| Telegram API Hash | SecretStore | AES-256-GCM | в логи/поддержку/ответы API |
| Мастер-ключ SecretStore | secrets/; входит в копию | файл 0600; portable v2 всегда зашифрован; local — только с фразой-паролем | в поддержку/публичный доступ |

Локальная модель угроз: LAN-соседи (порт 8787 — авторизация +
CSRF), контейнерный escape (минимизация привилегий), злонамеренный
релиз (проверка SHA256/манифеста), SSRF (allowlist).


Обычный локальный `.shmax` содержит мастер-ключ и не зашифрован целиком: защищайте его
как секрет или создавайте `.shmax.enc` через CLI/API. См. [бэкапы](backups.md).

## Синхронизация участников

Синхронизация Telegram обнаруживает молчавших участников через MTProto **бота**, а `chat_member` обновляет членство. Новые участники остаются не одобрены (`read_only`); Telegram admin не даёт SHMAX admin. API Hash хранится в SecretStore, сессия — только в памяти. Без необязательных настроек мост работает. Подробности, ограничения сети, backup и Privacy Mode: [Telegram-группа](telegram-group.md#автоматическое-обнаружение-участников).

### Изменение подписи пользователя

Административный PATCH существующего `nickname` требует авторизованной сессии и CSRF. Сервер удаляет крайние пробелы, принимает не более 64 Unicode-символов и запрещает переносы строк, управляющие и невидимые управляющие форматированием символы; соединители emoji сохраняются. Пустое значение снимает подпись. Операция не меняет ACL, членство или Telegram-admin; синхронизация не перезаписывает подпись.

## Переносимые копии

Portable v2 всегда шифрует весь файл Argon2id/AES-GCM, включая манифест.
Экспорт требует admin/owner, импорт/restore — owner, CSRF и rate limit.
Веб не получает Docker socket: hostd принимает только фиксированные операции
и job ID. Общая блокировка не допускает конфликтующих изменений на хосте.
Журнал записывается до pause/stop/swap; прерванные операции восстанавливаются
при запуске hostd. Hostd имеет только CAP_CHOWN/CAP_DAC_OVERRIDE/CAP_FOWNER
для чтения и установки данных с правильным UID/GID; веб остаётся без capabilities.
Страховочная previous/ не зашифрована: храните её как секрет.
См. [пределы и формат](backups.md), [политика владельца](restore.md).
