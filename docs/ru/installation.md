# Установка SHMAX

Поддерживаемая среда однострочного установщика: Debian 13 amd64, systemd и права
root/sudo. Нужен доступ к GitHub, репозиториям Debian/Docker и источникам зависимостей.
Оба способа ниже устанавливают одно и то же приложение и сохраняют данные в
`/var/lib/shmax`.

## Одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/SHMAX-Project/SHMAX/main/install.sh | sudo bash
```

Bootstrap скачивает последний опубликованный стабильный релиз официального
репозитория, проверяет подпись RSA-3072/SHA-256 встроенным публичным ключом,
контрольную сумму архива и внутренний список файлов. Только после проверки запускается
полный установщик. Docker Engine, Compose v2 и необходимые зависимости ставятся
автоматически через официальные APT-репозитории. Firewall и SSH не перенастраиваются.

Черновики и prerelease не устанавливаются. Пока первый стабильный выпуск не
опубликован, команда сообщит, что стабильный релиз отсутствует, и не установит SHMAX.

После проверки работоспособности установщик выведет адрес панели и ссылку мастера
первоначальной настройки. Откройте её в браузере и подключите MAX и Telegram.

Если SHMAX уже установлен, повторный запуск предложит безопасное обновление.
Подтверждение читается из терминала; без терминала обновление автоматически не
начинается. Существующие настройки, ключи и сессии не удаляются. Незавершённая
установка или данные без deployment требуют ремонта, а не новой установки.

## Ручная установка из архива

Этот способ сохраняется для администраторов, которым нужно сначала изучить файлы
или самостоятельно перенести пакет на сервер. Скачайте со
[страницы выпусков](https://github.com/SHMAX-Project/SHMAX/releases):

- `shmax-v0.1.0.tar.gz` — полный production-пакет;
- `SHA256SUMS` и `SHA256SUMS.sig` — контрольные суммы и подпись;
- публичный ключ `deploy/bootstrap/release-public.pem` из официального репозитория.

Проверьте отпечаток публичного ключа по официальной документации релиза, затем:

```bash
openssl dgst -sha256 -verify release-public.pem -signature SHA256SUMS.sig SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf shmax-v0.1.0.tar.gz
cd shmax-v0.1.0
# Изучите полный установщик перед запуском.
sudo bash deploy/installer/install.sh --mode install
```

Если проверка подписи или суммы завершилась ошибкой, не распаковывайте и не
запускайте пакет. Исходный архив не содержит собранного `frontend/dist`; для обычной
установки используйте production-архив. Даже при ручном переносе архива сборка
Docker получает base images, зависимости и Xray из сети.

## Обновление

Последний подписанный стабильный выпуск:

```bash
sudo shmax update
```

Обновление из вручную скачанного и проверенного production-архива:

```bash
sudo shmax update /полный/путь/shmax-v0.1.0.tar.gz
```

Оба сценария используют локальную транзакцию: сборка до остановки приложения,
проверенная холодная резервная копия, запуск кандидата, контроль готовности и
возврат прежнего образа вместе с данными при ошибке. Отчёт сохраняется в защищённом
каталоге `/var/backups/shmax`.

## Режимы полного установщика

Запускаются из полного распакованного архива; добавьте `--dry-run` для просмотра плана.

| Режим | Действие |
|---|---|
| `--mode install` | Первичная установка, подготовка каталогов, Docker и служб |
| `--mode repair` | Восстановление deployment с сохранением данных |
| `--mode upgrade` | Ручное обновление deployment с сохранением данных; перед запуском сделайте копию |
| `--mode uninstall` | Удаление приложения с сохранением данных |

Для обычного обновления используйте `shmax update`: он дополнительно выполняет
резервное копирование, проверку готовности и откат. `--purge` удаляет данные и требует
отдельного подтверждения; он не нужен для обычного удаления приложения.

## Каталоги и службы

- `/opt/shmax` — deployment, compose, полный установщик и boot-скрипт.
- `/var/lib/shmax` — база, настройки, ключи, сессии и локальные копии.
- `/opt/shmax-hostd` — отдельный root-owned Python runtime hostd и CLI.
- `shmax-hostd.service` — ограниченный host-helper; `shmax-boot.service` — запуск после перезагрузки.

Оба systemd unit проверяются до запуска. Контейнер работает без root и получает
ограниченный сокет hostd, без Docker socket. Данные сохраняются при замене контейнера.
