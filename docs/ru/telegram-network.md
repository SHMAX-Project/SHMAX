# Telegram сеть: Direct / SOCKS5 / HTTP / Xray

Шаг «Telegram сеть» определяет, КАК контейнер достучится до Bot
API. Выбранный режим сохраняется и восстанавливается при
перезапуске; прямого фолбэка нет (fail-closed).

## Режимы

- **Direct** — если Bot API доступен напрямую.
- **SOCKS5 / HTTP** — внешний прокси (host, порт, опц. логин/пароль).
- **Xray-подписка** — URL подписки VLESS/Trojan; SHMAX сам скачает
  (при установке) и запустит локальный Xray, направив через него
  ТОЛЬКО Telegram. SOCKS Xray слушает только 127.0.0.1.

## Первая проверка бота

Первый getMe бота ВСЕГДА идёт через сохранённую сеть (probe без
polling). Если сеть не работает — верификация бота тоже не
пройдёт: чините сеть, а не токен.

## Смена режима

Откройте настройки бота со страницы «Telegram» и шаг «Telegram сеть» мастера.
После изменения проверьте соединение. Сеть MAX независима от Telegram: direct, HTTP, SOCKS5 или Xray; см. [сеть MAX](max-network.md).

Для необязательной полной синхронизации требуется MTProto-доступ Telegram.
Вспомогательный клиент использует сохранённый SOCKS/HTTP/Xray или MTProxy; без прокси
подключается напрямую. Доступность Bot API через HTTP сама по себе не гарантирует
доступность MTProto. Ошибка прокси не вызывает перехода на Direct; ошибка
синхронизации не останавливает обычный мост.


## Синхронизация участников

Синхронизация Telegram обнаруживает молчавших участников через MTProto **бота**, а `chat_member` обновляет членство. Новые участники остаются не одобрены (`read_only`); Telegram admin не даёт SHMAX admin. API Hash хранится в SecretStore, сессия — только в памяти. Без необязательных настроек мост работает. Подробности, ограничения сети, backup и Privacy Mode: [Telegram-группа](telegram-group.md#автоматическое-обнаружение-участников).
