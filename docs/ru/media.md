# Фото и стикеры

Telegram → MAX фото проходят общий нормализатор aiogram: выбирается наибольшая PhotoSize по площади/размеру и используется именно `file_id`, а не `file_unique_id`. `getFile` и поток скачивания идут через одну настроенную сессию Bot API: Direct, SOCKS5, HTTP или внутренний Xray SOCKS. Прямой запасной обход прокси не используется. Полученный файл проверяется, получает расширение по формату, передаётся PyMax `Photo(path=...)` и отправляется как вложение, включая caption и native reply ID.

«Подпись в MAX» сохраняется: `[Роман]: Вот документ` плюс настоящее фото. Текстовая заглушка не считается доставленным фото. MAX → Telegram фото сохраняют обычный путь доставки и имена MAX-авторов.

Стикеры:

| Источник | Результат |
| --- | --- |
| Telegram static WebP | Прозрачный PNG как фото MAX |
| MAX static image sticker | Статический PNG sticker Telegram, если укладывается в требования 512 px / 512 КиБ; иначе настоящее фото |
| Telegram TGS/animated или WebM/video | Доступный thumbnail как статическое изображение; без thumbnail — одна понятная текстовая заглушка |
| MAX animated sticker с пригодным растровым URL | Первый кадр/статическое представление; неподдерживаемый raster/Lottie-only — текстовая заглушка |

Полная анимация TGS/WebM не конвертируется. FFmpeg/Lottie-стек не добавляется. Используется существующий Pillow/кодеки ARMv7: отдельный процесс, 8 секунд wall time, 5 секунд CPU, 256 МиБ адресного пространства на Linux, 4 Мп для стикера, 25 Мп для фото. Входной sticker до 5 МиБ, загрузка до 20 МиБ/35 секунд. Допустимы JPEG/PNG/WebP; неверный ответ HTML, пустой файл, слишком большой размер или некорректный формат отклоняются с уборкой временного файла. MAX downloads разрешены только по HTTPS с доверенных MAX/CDN-доменов; редиректы запрещены.

Очередь различает MEDIA_PENDING и MEDIA_FALLBACK; успешная отправка вложения фиксируется в диагностике как MEDIA_DELIVERED, ошибка — MEDIA_FAILED. Заглушка остаётся обычной текстовой доставкой, без заявления об успехе media. Cache сохраняется на retries и убирается по завершению/TTL.

Диагностика содержит direction/category/operation/exception type/фиксированный безопасный reason/correlation ID. Не включаются URL с токенами, proxy passwords, subscriptions, бинарные данные или содержимое SecretStore. Сбой upload/send MAX отличается от download/validation Telegram. Внешняя доставка остаётся at-least-once: сбой записи mapping после внешней отправки может потребовать retry; обещания exactly-once сети нет.


### Совместимость загрузки PyMax 2.4.1

SDK читает `photoIds` из URL инициализации до загрузки. SHMAX использует обёртку отдельного клиента: подписанный URL не меняется; отсутствие ID в query допускается только при ровно одной проверенной паре фото/токен в фактическом ответе загрузки. ID из query должен совпадать с ответом. Некорректные или неоднозначные ответы завершаются без отправки сообщения. Фото профиля и остальные методы загрузки используют реализацию SDK. Причина отсутствия query в ответе живого сервера пока не подтверждена.

Ссылки `document:` и `file:` используют SDK `File`; исходное имя сохраняется отдельно от пути кэша. Избранное (`chat_id=0`) — допустимое назначение для текста, фото, документов, преобразованных статических стикеров и ответов.

Временные ошибки получают ограниченные повторы (восемь попыток); ошибки схемы, авторизации и сессии сохраняют запись очереди и кэш для ручной проверки. Потеря финального подтверждения после загрузки останавливает автоматическую повторную отправку с `delivery_confirmation_uncertain_review_before_retry`: перед повтором проверьте MAX. Ручной повтор сбрасывает счётчик в той же записи с тем же ключом идемпотентности. Сохраняется прежнее ограничение at-least-once при доставке и последующей ошибке записи соответствия сообщений. Диагностика содержит только операцию, известные имена полей схемы, наличие query ID, статус и корреляцию; логи SDK очищаются в контексте текущей задачи доставки медиа.

## MAX → Telegram: несколько вложений (v0.1.1)

Все поддерживаемые фото сохраняются; Bot API группирует подряд идущие фотографии
по 2–10 в существующую mapped forum topic. Caption/авторство сообщения используется
один раз. Документы и mixed media идут отдельными отправками в исходном порядке.
Прогресс confirmed sends хранится в очереди; aliases поддерживают ответы к каждому
Telegram ID. При временной ошибке retry возобновляет оставшиеся элементы, при
постоянной — фиксирует partial failure и сохраняет остальные валидные отправки.
Ограничения проверки и ambiguous-timeout semantics: [release notes](../../release/v0.1.1/RELEASE_NOTES.ru.md).

## v0.2.0

Настройки маршрутов, подписей источника/автора и прав отправки задаются отдельно по Telegram-группам. Один чат MAX может иметь несколько назначений; админский обзор создаёт темы автоматически. Постоянные задания и соответствия сообщений разделены по назначениям; альбомы сохраняют состав и тему в каждой группе. Сеть MAX настраивается независимо от Telegram. См. [группы и права](multi-group.md), [сеть MAX](max-network.md), [медиа](media.md).
