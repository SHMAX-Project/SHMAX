# Диагностика по симптомам

Формат: Симптом → Слой → Безопасные проверки → Что делать.

## Веб-интерфейс не открывается
Слой: хост/сеть. Проверки: `systemctl status shmax-boot.service`;
`docker ps`; `docker port shmax-web-1`; `curl -fsS
http://<bind-address>:<port>/health/ready`. Действие: если контейнер
running, а `docker port` пуст — `cd /opt/shmax && docker compose
up -d --force-recreate` (boot-юнит делает это сам после ребута).

## MAX unhealthy
Слой: MAX-сессия. Проверки: Диагностика → MAX; `docker logs
shmax-web-1 --tail 50`. Действие: повторный вход (шаг MAX);
если «Требуется 2FA» — включите 2FA в приложении MAX.

## Telegram unhealthy
Слой: сеть/бот. Проверки: Диагностика → Telegram; transport
страница → probe. Действие: сменить/починить сеть; проверить
токен.

## Через Xray не работает, напрямую работает
Слой: Xray. Проверки: `/api/telegram/xray/status` (state, pid);
логи. Действие: выбрать другую ноду; проверить подписку.

## Бот не проверяется
Слой: сеть+токен. Проверки: правильность токена у BotFather;
проба сети. Действие: сохранить токен заново после починки сети.

## Группа не подключается
Слой: Telegram. Проверки: Темы включены? Бот админ? Права
manage_topics/send? Действие: см. telegram-group.md.

## `/shmax_connect` игнорируется
Слой: слушатель. Проверки: Диагностика → Telegram HEALTHY;
права администратора и /setprivacy → Disable; код не истёк.
Отсутствие команды не доказывает включённый Privacy Mode; getMe не проверяет доставку группы. Действие: выпустить код
заново (проверяется живой poller).

## Сообщения дублируются
Слой: очередь/эхо. Проверки: `docker logs` на «echo»/«duplicate».
Действие: обновиться (echo-registry); сообщить issue.

## Ответ уходит не в тот чат MAX
Слой: mapping. Проверки: маршруты на «Чаты». Действие:
пересоздать тему маршрута.

## Вложение не поддерживается
Ожидаемо: `[Неподдерживаемое вложение]` или с человекочитаемым
типом (например, «опрос»). Статические стикеры передаются изображением;
анимированные/видео — preview при его наличии. См. [Медиа](media.md). Текст доставляется один раз.

## Бэкап не создаётся
Проверки: место на диске (`df -h /var/lib/shmax`); права.
Действие: см. logs.md.

## Обновление не проверяется
Проверки: `SHMAX_UPDATE_REPO_URL` задан? GitHub доступен?
Действие: повторить «Проверить обновления»; мост не страдает.

## Произошёл откат обновления
Смысл: новая версия не прошла host-readiness. Действия: `docker
logs`, проверить место, повторить позже; предыдущая версия уже
работает, если откат прошёл успешно. При ошибке самого отката
сохраните данные и следуйте явно выданным инструкциям восстановления.

## SHMAX не вернулся после ребута
Слой: boot. Проверки: `systemctl status shmax-boot.service`;
`journalctl -u shmax-boot -n 50`. Действие: исправить сеть/IP;
unit сам пересоздаст контейнер, когда адрес появится.

## Порт 8787 занят/недоступен
Проверки: `ss -ltnp | grep 8787`. Действие: сменить bind в
`/opt/shmax/compose.yaml` + `.env`, затем recreate.

## Проблема миграции БД
Проверки: `docker logs` (alembic). Действие: НЕ удалять БД;
собрать отчёт (SUPPORT.md).


## Синхронизация участников

Синхронизация Telegram обнаруживает молчавших участников через MTProto **бота**, а `chat_member` обновляет членство. Новые участники остаются не одобрены (`read_only`); Telegram admin не даёт SHMAX admin. API Hash хранится в SecretStore, сессия — только в памяти. Без необязательных настроек мост работает, если откат прошёл успешно. При ошибке самого отката
сохраните данные и следуйте явно выданным инструкциям восстановления. Подробности, ограничения сети, backup и Privacy Mode: [Telegram-группа](telegram-group.md#автоматическое-обнаружение-участников).

При ошибке переноса см. [Восстановление](restore.md): неверный пароль не меняет данные, rollback_failed требует сохранения страховочной копии и журнала.
