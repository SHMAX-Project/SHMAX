# Что такое SHMAX и зачем

## Продуктовая модель

```
MAX (обычный аккаунт пользователя)
        ↕  SHMAX
Telegram-бот
        ↕
приватные Telegram-супергруппы с форум-темами
```

Каждый выбранный чат MAX получает **свою тему** в Telegram-группе.
Сообщения ходят в обе стороны: ответы в теме уходят автору в MAX,
автор подписан (`[Имя]:`), медиа доставляется с подписью.

Зачем: MAX и Telegram — разные экосистемы. SHMAX соединяет их на
вашем собственном сервере, без облаков посередине: вы владеете
базой, сессиями и логами.

## Ключевые свойства

- **Самостоятельный**: Debian 13 + Docker, без внешних сервисов
  SHMAX-разработчика.
- **Одноразовое приложение, постоянные данные**: контейнер можно
  удалять/заменять/откатывать — `/var/lib/shmax` не трогается.
- **Сеть для Telegram настраивается**: Direct, SOCKS5, HTTP-прокси,
  Xray-подписка (VLESS/Trojan, Reality). Xray для MAX и Telegram настраивается независимо; сеть MAX: direct, HTTP, SOCKS5 или Xray — см. [сеть MAX](max-network.md).
- **ACL**: одобренные пользователи Telegram, роли, блокировки.
- **Резервные копии и восстановление**, обновления из GitHub
  Releases с проверкой SHA256 и автоматическим откатом.

## Что SHMAX НЕ делает

- Не читает переписку вне выбранных чатов.
- Не публикует SOCKS Xray в LAN (только 127.0.0.1 внутри узла).
- Не отправляет телеметрию (см. [../../PRIVACY.md](../../PRIVACY.md)).
- Не поддерживает MAX-ботов (только обычные аккаунты).

## v0.2.0

Настройки маршрутов, подписей источника/автора и прав отправки задаются отдельно по Telegram-группам. Один чат MAX может иметь несколько назначений; админский обзор создаёт темы автоматически. Постоянные задания и соответствия сообщений разделены по назначениям; альбомы сохраняют состав и тему в каждой группе. Сеть MAX настраивается независимо от Telegram. См. [группы и права](multi-group.md), [сеть MAX](max-network.md), [медиа](media.md).
