# Обновления (GitHub Releases)

## Модель

- Источник: `SHMAX_UPDATE_REPO_URL=https://github.com/<owner>/<repo>`
  (строго HTTPS GitHub; иначе «источник не настроен»).
- Каналы: **stable** (без prerelease) и **beta** (с prerelease).
  Версии — SemVer (0.2.0-beta.2 < 0.2.0).
- Автопроверка раз в 24 часа + кнопка «Проверить обновления».
  GitHub недоступен → мост работает, страница показывает статус.
- Доверие: release-manifest.json и/или SHA256SUMS (обязаны
  совпадать), 64 hex sha256, артефакт `shmax-vX.Y.Z.tar.gz`.
  URL-политика: только HTTPS GitHub-происхождения; токен (если
  задан) уходит ТОЛЬКО на api.github.com; каждый redirect
  перепроверяется.

## Установка

- Только вручную: «Обновить» (появляется, когда есть обновление И
  доступен shmax-hostd). Никакого авто-apply.
- Транзакция на хосте (через `shmax update apply`, вызываемый
  hostd): скачать → проверить SHA256 **скачанных байт** →
  safety-бэкап → staging → установить в /opt/shmax (compose.yaml и
  .env оператора сохраняются) → docker compose up → проверка
  готовности **по хост-URL** → успех/откат.
- Откат: предыдущий деплой хранится до успеха; при любом сбое
  возвращается предыдущая версия и проверяется её готовность.
  Если откат тоже упал — явное сообщение с ручными шагами.
- `/var/lib/shmax` никогда не заменяется релизом.

## Статусы UI (по-русски)

«Установлена последняя версия.» / «Обновление доступно» /
«Не удалось проверить обновления.» / «Источник обновлений не
настроен». Кнопки без hostd не предлагают установку.

## Штатная команда v0.1.2

`sudo shmax update` загружает последний stable package и проверяет подпись существующим встроенным ключом. Для локального подписанного production-архива: `sudo shmax update /path/to/shmax-v0.1.2.tar.gz` после проверки подписи и суммы. UI/hostd по-прежнему требуют явного действия администратора.

Образ собирается до остановки. Затем updater создаёт холодную копию persistent data с проверкой содержимого/прав и SQLite integrity, запускает кандидат и проверяет свежую готовность настроенных MAX/Telegram. При отказе возвращает точный прежний образ, deployment и проверенные холодные данные; диагностика остаётся в защищённом отчёте. Каталог данных не заменяется содержимым release archive; при rollback восстанавливается его собственная cold backup. Сохраняйте полную копию вне неисправного диска; config-only backup её не заменяет. Исторические failed deliveries не переотправляются автоматически.
